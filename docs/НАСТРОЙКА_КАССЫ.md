# Настройка кассы и сайта — инструкция для владельца

Документ для человека, который настраивает **Frontpad (кассу)** и **админку сайта**, без программирования.

Сайт: https://shashlik.loomixx.ru  
Админка сайта: https://shashlik.loomixx.ru/admin → раздел **Настройки** → вкладка **Касса**

---

## Что должно получиться в итоге

1. Клиент оформил заказ на сайте → заказ появился в кассе.
2. Суммы в кассе совпадают с сайтом (товары, добавки, скидки, бонусы сайта).
3. Когда вы меняете статус заказа в кассе → статус на сайте обновляется сам (у клиента на странице заказа и в админке).
4. Стоп-лист из кассы скрывает недоступные позиции на сайте.

Если чего-то из этого нет — смотрите раздел «Если что-то не работает» в конце.

---

## Важные правила (прочитайте один раз)

| Правило | Почему |
|--------|--------|
| **Не меняйте глобальный адрес webhook в настройках API кассы**, если там уже стоит другая система (например FoodSoul) | Сайт передаёт свой адрес **внутри каждого заказа**. Глобальный URL чужой интеграции трогать не нужно |
| У товаров для сайта в кассе должен быть **цифровой артикул** | Без артикула позиция не уйдёт в кассу |
| Добавки и соусы — тоже **отдельные товары с артикулами** в кассе | Иначе добавка останется только на сайте |
| Телефон клиента на сайте и в кассе — в **одной маске** (обычно `+7…`) | Иначе карта клиента в кассе может не находиться |
| Бонусы **сайта** и бонусы **кассы** — разные системы | Сайт списывает свои баллы сам; в кассу уходит уже итоговая скидка по сумме |

Секрет API кассы и служебный токен сервера настраивает тот, кто обслуживает сервер. В админке сайта секрета нет — так и должно быть.

## Часть 1. Что сделать в кассе Frontpad

### 1.1. Включить API

1. Откройте Frontpad → настройки / общие (как у вас называется раздел API).
2. Включите API.
3. Сохраните **секрет** и передайте его человеку, который ставит сервер сайта (в программу кассы его «вбивать» на сайт не нужно — он уже на сервере).

После включения API **перезапустите программу кассы**, если Frontpad об этом просит.

### 1.2. Артикулы товаров

Для всего, что продаётся **онлайн**:

- основное блюдо (шаурма, шашлык и т.д.);
- размер / вариант мяса — если в кассе это отдельные позиции;
- платные добавки;
- соусы;
- при необходимости — отдельная позиция «Доставка» и «Упаковка».

Артикул: **только цифры**, уникальный, как в справочнике Frontpad для интернет-магазина.

В админке сайта у товара / размера / добавки должен быть **тот же** артикул.

### 1.3. Разрешить менять цену в заказе извне (обязательно для совпадения сумм)

Сайт передаёт в кассу цены «как на сайте» и скидку (промокод + бонусы сайта).

В Frontpad должно быть разрешено **изменение цены при приёме заказа через API** (формулировка в кассе может отличаться: «разрешить изменение цены», «цены из API» и т.п.).

Без этого касса может проигнорировать цены сайта — чек не совпадёт.

### 1.4. Справочники кодов (выпишите цифры на бумажку)

В кассе найдите и запишите **числовые коды**:

| Что | Где обычно смотреть | Зачем |
|-----|---------------------|--------|
| Вариант оплаты «самовывоз» | Справочник «Варианты оплаты» | Код оплаты для заказов «заберу сам» |
| Вариант оплаты «доставка» | то же | Код для доставки |
| Канал / филиал / точка | соответствующие справочники | Чтобы заказ попал в нужную точку (если у вас несколько) |
| Отметки заказа | «Отметки заказа» | Необязательно; метки вроде «с сайта» |
| Статусы заказа | статусы в кассе | Чтобы сайт понимал «готовится / в доставке / выполнен / отменён» |

Типичные коды статусов (проверьте у себя — у вас могут отличаться):

| Код в кассе | Обычно значит | На сайте станет |
|-------------|---------------|-----------------|
| 1 | В работе / готовится | Готовится |
| 3 | В доставке | В доставке |
| 5 | Выполнен | Выполнен |
| 9 | Отменён | Отменён |

Нужно не больше **5** кодов статусов для уведомлений сайта.

### 1.5. Бонусы самой кассы (Frontpad)

Сайт **не** управляет бонусами Frontpad.

Рекомендация: в кассе начисление баллов Frontpad лучше поставить на **закрытие / выполнение** заказа, а не на момент «заказ только что пришёл из API» — иначе клиент может получить баллы кассы раньше, чем заказ реально выполнен.

Бонусы **сайта** (монетки на сайте) настраиваются отдельно в админке → **Бонусы**.

## Часть 2. Что настроить в админке сайта

Вход: `/admin` под учётной записью **администратора**.  
Путь: **Настройки → вкладка «Касса»**.  
После правок нажмите **Сохранить**.

### 2.1. Главные тумблеры

| Тумблер | Как должно быть для работы |
|---------|----------------------------|
| **Отправка заказов в кассу** | **Включён**. Если выключен — заказы на сайте создаются, но в кассу не уходят (режим проверки) |
| **Синхронизация каталога** | **Включён**, если хотите автообновление стоп-листа и возможность тянуть товары из кассы |
| **Передавать цены в кассу** (`product_price`) | **Включён**, если в кассе разрешено менять цену (см. п. 1.3). Нужен, чтобы суммы совпадали |

### 2.2. URL вебхука

Поле: **URL вебхука (без токена)**

Обычно:

`https://shashlik.loomixx.ru/api/webhooks/frontpad/status`

Токен сервер добавит сам.  
Глобальный webhook в кабинете Frontpad **не меняйте**, если он занят другой программой.

### 2.3. Коды оплаты и точка

| Поле в админке | Что вписать |
|----------------|-------------|
| Код оплаты (самовывоз) | Код из п. 1.4 |
| Код оплаты (доставка) | Код из п. 1.4 |
| Канал / Филиал / Точка | Коды из справочников кассы (если пользуетесь) |
| Артикул упаковки | Артикул позиции «упаковка» в кассе, если берёте плату за упаковку |
| Артикул доставки | Артикул позиции «доставка» в кассе, если доставка платная |

Если артикул упаковки/доставки пустой — сайт просто не добавит эту строку в кассу (плата на сайте при этом считается по своим правилам вкладки «Экономика»).

### 2.4. Webhook-статусы — обязательно

Блок **«Webhook-статусы»**.

Сюда впишите коды статусов кассы, при которых касса должна **сообщить сайту** (не больше 5), например: `1`, `3`, `5`, `9`.

**Если список пустой — статусы с кассы на сайт не приедут.** Это самая частая причина «в кассе поменял, на сайте не изменилось».

### 2.5. Маппинг статусов

Блок **«Маппинг статусов кассы»**.

Для каждого кода из п. 2.4 укажите, какой статус показать на сайте:

| Код кассы | Статус на сайте |
|-----------|-----------------|
| 1 | Готовится |
| 3 | В доставке |
| 5 | Выполнен |
| 9 | Отменён |

Если у вас другие коды — подставьте свои.  
Неизвестный код сохранится «для сведения», но статус на сайте не сменится, пока не добавите строку в маппинг.

### 2.6. Отметки заказа (по желанию)

Числовые коды из Frontpad → Отметки заказа. Не больше 10.  
Нужны только если хотите помечать заказы с сайта специальной меткой в кассе.

### 2.7. Источник справочника цен

| Значение | Смысл |
|----------|--------|
| **Сайт** | Цены правите на сайте; касса в своём справочнике сама по себе |
| **Касса** | Можно подтянуть цены из кассы в товары сайта (отдельная операция в товарах / ценах кассы) |

Поменять цену на сайте так, чтобы она **навсегда** записалась в справочник кассы, **нельзя** — у кассы нет такой команды. В каждом заказе сайт может только передать цену «на этот заказ».

### 2.8. Синхронизация кнопок

| Кнопка | Что делает | Ограничение |
|--------|------------|-------------|
| **Обновить товары кассы** | Забирает список товаров с артикулами и ценами из кассы | **Не чаще 1 раза в час** (иначе касса может заблокировать доступ) |
| **Обновить стоп-лист** | Обновляет, что снято с продажи | Можно чаще; авто — примерно раз в 15 минут, если включена «Синхронизация каталога» |

## Часть 3. Другие вкладки настроек (кратко)

### «Заведение»

Телефон, адрес, часы, тексты на сайте.  
Тумблер **«Принимаем заказы»** — если выключить, оформить заказ нельзя.

### «Экономика»

Минимальная сумма заказа, стоимость доставки, порог бесплатной доставки.

### «Бонусы» (отдельный раздел админки)

Своя программа лояльности сайта.  
При оплате бонусами сайта сумма в кассе уменьшается так же, как на сайте (скидка уходит в заказ кассы).  
Баллы Frontpad при этом не трогаются.

## Часть 4. Чеклист «можно открывать»

Отметьте галочками:

### В кассе

- [ ] API включён, программа перезапущена
- [ ] У онлайн-товаров и добавок есть цифровые артикулы
- [ ] Разрешено изменение цены заказа через API
- [ ] Записаны коды оплаты самовывоз / доставка
- [ ] Понятные коды статусов (какие числа = готовится / доставка / готов / отмена)
- [ ] Глобальный webhook другой системы **не трогали**

### На сайте (Настройки → Касса)

- [ ] «Отправка заказов в кассу» включена
- [ ] URL вебхука заполнен (`…/api/webhooks/frontpad/status`)
- [ ] «Передавать цены в кассу» включено (и в кассе это разрешено)
- [ ] Коды оплаты заполнены
- [ ] **Webhook-статусы** не пустые (например 1, 3, 5, 9)
- [ ] Маппинг статусов совпадает с кодами кассы
- [ ] У товаров и добавок на сайте проставлены те же артикулы, что в кассе
- [ ] Настройки сохранены

### Проверка одним тестовым заказом

1. Оформите небольшой заказ с сайта (лучше с одной добавкой).
2. В админке → **Заказы**: заказ есть, нет длинной ошибки кассы (поле ошибки пустое или только «предупреждение»).
3. В кассе заказ появился, суммы совпадают.
4. Смените статус в кассе → через несколько секунд статус на сайте / на странице заказа обновился.
5. Поставьте позицию в стоп в кассе → «Обновить стоп-лист» → на сайте позиция недоступна.

## Если что-то не работает

| Симптом | Что проверить |
|---------|----------------|
| Заказ на сайте есть, в кассе нет | Тумблер «Отправка заказов в кассу»; ошибка в карточке заказа; артикулы; API кассы включён |
| Суммы разные | «Передавать цены»; в кассе разрешено менять цену; артикулы добавок; артикулы доставки/упаковки |
| Статус в кассе меняется, на сайте нет | **Webhook-статусы** не пустые; URL вебхука верный; маппинг кода; заказ реально ушёл в кассу (есть номер Frontpad) |
| «Товары кассы» не обновляются | Лимит 1 раз в час; «Синхронизация каталога» включена |
| Добавка не попала в кассу | У добавки на сайте и в кассе должен быть один и тот же цифровой артикул |
| Красная ошибка в настройках кассы | Прочитайте текст «Последняя ошибка кассы» — часто неверный секрет, лимит запросов или неверный артикул |

Состав заказа, изменённый **вручную только в кассе**, на сайт **не синхронизируется** — касса умеет сообщать сайту только **статус**. Состав на сайте — тот, что клиент оформил (или что поправили в админке сайта).

## Кому что отдавать

| Кому | Что |
|-----|-----|
| Владелец / управляющий | Этот файл; коды оплаты и статусов; артикулы |
| Тот, кто ведёт сервер | Секрет API Frontpad, токен вебхука, перезапуск сервисов — **не публиковать** и не писать в чаты с клиентами |

Вопросы по полям админки: вкладка **Настройки → Касса** — у многих полей есть короткая подсказка под названием.
